# Kernel profile and optimisation pass, 2026-09-16

What was done, in order, with the numbers that decided each step. The full
measurements and method are in [kernel_profile.md](kernel_profile.md); this is
the summary and the map of what changed where. Everything is bit-exact: the
suite's goldens pass unchanged, and every converted filter's exact score stream
was compared against the committed library on two 65,536-seed ranges.

## 1. Where the time went (before any change)

- **Intra-warp divergence** was the first-order loss for every branchy filter
  (47% to 84% of wall time): lanes idle behind the slowest lane in lock-reroll
  loops, item-type branches and early exits, and the fp64 pipe is charged its
  full 16 clocks per warp instruction however many lanes are active (measured:
  a node creation or a draw costs the warp the same with 1, 8 or 32 lanes).
- **fp64 pipe throughput** bound everything else. With divergence removed, every
  filter's time was reproduced within 2% by counts x unit costs: a hashed
  character 30 fp64-op equivalents, a draw 23, a new RNG node ~350 (about 12
  characters). Node-name hashing was 52% to 98% of the non-divergent time in
  every filter but the deck one.
- Everything else was small or ruled out: node cache and scan ~2% of a draw,
  local memory free, integer RNG core hidden under fp64, fp64 latency fully
  hidden at 16 warps/SM, clocks steady at 2850 MHz with no throttling, host and
  launch overhead ~0.11 s per process. Two exceptions: deriving the seed from
  its rank cost 0.83 ns per seed (a 64-byte vector spill per digit), and
  `deep_negative_shops` had an intermittent 4x to 18x slow mode.

## 2. Library changes (`lib/`)

| change | file | effect |
|---|---|---|
| Name-suffix hash-state cache: the state after the seed and the last m parts of a node name is memoised (64 entries, `SUFFIX_CACHE_BITS`), longest suffix first; node-name hashing is out of line (`rng_node_hash_name`) and decodes the parts from the packed key | `instance.cl` | hashed characters -17% to -29% on reroll-heavy filters; negative_tags -17%, deep shops -9% |
| `ph_step`: `trunc` instead of the fp64->int64->fp64 round trip, NVIDIA `rcp.approx.ftz.f64` as the Newton seed (probed bit-identical over 5.1e9 inputs incl. 0, inf, NaN; a `pi*pos` table was probed too and dropped as no gain) | `util.cl` | -7% per node creation |
| `s_from_rank` / `s_tell` with compile-time vector indices (no per-digit spill) | `seed.cl` | per-seed floor 1.02 -> 0.585 ns; deck filter -12% |
| `randchoice_common_batch`: many `randchoice_common` requests with reroll chains depth-major over each lane's own pending list; pre-warms the shared `_resample<k>` suffix states at depths 1-2 | `instance.cl` | turns "some lane rerolls" per slot into max over lanes of a binomial count |
| `shop_items_dense`: a shop window in phases (types, rarities, identities per pool via the batch helper, stickers, editions, other items), `SHOP_*` flags to skip unread streams, windows of `SHOP_MAX_ITEMS` | `functions.cl` | the deep-shops restructuring made general |
| `DIAG_COUNTERS` operation counters (compiled out by default; PTX verified byte-identical) | `instance.cl`, `functions.cl` | cost attribution only |

## 3. Host change (`immolate.c`)

`--launch_seconds <S>` (default 1): the plain single-pass search runs its
range in launches of about S seconds instead of one launch. Cost 0.3% on the
cheap filter. It fixes silent record loss in the print path: the kernel printf
buffer holds ~110k records per launch, so a single launch of 100M deck seeds at
cutoff 7 printed 35% of the true 316,056 records, 0.2 s launches 99.9%. Runs
expected to print more than ~100k records should still use `--to` (exact).

It did **not** fix the deep-shops slow mode, which is confined to the two
kernels containing `printf` (`search`, `search_ranks`) at 16 work-groups per SM
for that filter, comes and goes over a session, and shows 70 W at full clock
(stalled SMs). `-g 1176` avoided it in 8 of 8 runs and is 9% faster for that
filter; the default geometry is unchanged. Root cause not identified.

"Floor" is the mandatory arithmetic at the measured pipe rate with no
divergence; "ideal" is the irreducible operation count at the nominal pipe
rate. What remains is documented per filter in kernel_profile.md: sixth_sense's
42% early exits and per-lane ante count, early_ante_perkeo's per-card poll
loop, negative_tags' binomial max over lanes, early_negative_rares' per-seed
frame size and per-ante voucher chains.

## 6. Tooling added

- `diagnostics/prim_*.cl`: primitive micro-benchmarks (slope between two `PRIM_K`).
- `diagnostics/diag_uni_*.cl`: warp-uniform seed probes (`UNI_MASK`), the divergence measurement.
- `diagnostics/diag_count_*.cl`: per-seed operation counters via `--scores_to`.
- `diagnostics/probe_phstep_variants.cl`: bit-exactness probe for `ph_step` rewrites.
- `tests/profile_kernel.py`, `tests/profile_analyze.py`, `tests/ptx_mix.py`, plans in `tests/kernel_profile/` (`verify.json` re-measures after a library change; compare against the draw slope, which no change touches, not against the primitive being changed).

## 7. How each step was verified

`python tests/run.py --profile correctness` after every step (and `--profile
breadth` once, 32.2M seeds); exact `--scores_to` streams of each converted
filter diffed against the committed library built in a temporary worktree;
two-pass vs single-pass supplier files compared with `tests/compare.py` where a
prefilter was involved; timings from `tests/kernel_profile/verify.json`.
